# Abstract

This document presents a comprehensive technical description, architectural review, and proposed redesign of the **TESS Exoplanet Detection and Bayesian Characterization Pipeline**. The pipeline is designed to automatically identify transiting exoplanets in TESS light curves, characterize the host star, and infer planetary parameters through Bayesian modeling using **PyMC**, **exoplanet**, and **celerite2 Gaussian Processes**.

Unlike traditional pipeline documentation, this report combines

- software architecture,
- scientific methodology,
- statistical analysis,
- computational considerations, and
- algorithmic optimization

into a single reference document.

The report has four primary objectives.

1. Document the complete implementation of the current pipeline.
2. Explain the mathematical and statistical reasoning behind each module.
3. Identify limitations and potential sources of systematic error.
4. Design an optimized next-generation pipeline while preserving the existing modular architecture.

The report is intended to serve both as developer documentation and as the basis for the methodology section of future scientific publications.

# Scientific Objectives

The pipeline has four scientific goals.

1. Automatically retrieve TESS observations for any astronomical target.

2. Detect one or more transiting planets using modern transit-search algorithms.

3. Characterize the host star using archival stellar catalogs.

4. Estimate planetary parameters through Bayesian inference while accounting for correlated stellar variability.

---

# Pipeline Philosophy

Rather than performing a fully Bayesian search over the entire parameter space, the pipeline follows a **hierarchical approach**.

The computationally inexpensive stages progressively reduce the parameter space before the expensive Bayesian inference stage is executed.

The philosophy is illustrated below.

```text
Large Parameter Space
        │
        ▼
Target Resolution
        │
        ▼
Archive Information
        │
        ▼
Light Curve Download
        │
        ▼
Preprocessing
        │
        ▼
TLS/BLS Search
        │
        ▼
Planet Candidates
        │
        ▼
Bayesian Refinement
        │
        ▼
Planet Parameters
```

This strategy reduces computational cost by several orders of magnitude while preserving statistical rigor during the final inference stage.

# Pipeline Components

The current implementation consists of the following major modules.

| Module | Purpose |
|----------|----------|
| Target Resolution | Resolve object identifiers and coordinates |
| Archive Query | Retrieve literature orbital periods |
| Data Download | Download TESS light curves |
| Preprocessing | Clean, normalize and detrend observations |
| Period Search | Detect transit signals using TLS/BLS |
| Stellar Characterization | Estimate stellar parameters |
| Bayesian Inference | Joint transit + GP model fitting |
| Planet Parameters | Derive physical quantities |
| Diagnostics | Convergence and quality assessment |
| Visualization | Produce figures and reports |

# Software Architecture

The pipeline follows a modular stage-based architecture.

Each stage performs one logically independent task.

```text
             Configuration
                    │
                    ▼
             TESSAnalysis
                    │
     ┌──────────────┼──────────────┐
     ▼              ▼              ▼
 Target        PipelineResults    Logger
                    │
                    ▼
         Sequential Processing Stages
                    │
                    ▼
            Scientific Products
```

The stages communicate exclusively through the shared **PipelineResults** object.

This architecture minimizes coupling between modules while allowing future stages to be added with minimal modification.

---

# Design Principles

The implementation follows several software engineering principles.

## Modularity

Every scientific operation is implemented in an independent module.

Examples include

- preprocessing
- transit detection
- stellar characterization
- Bayesian inference

This simplifies testing and future development.

---

## Reproducibility

Every important result is stored in the PipelineResults object.

Intermediate products are never discarded.

Examples include

- cleaned light curves
- detrended light curves
- archive periods
- detected planets
- posterior samples
- derived parameters

This allows every stage of the analysis to be reproduced.

---

## Extensibility

New algorithms can be added without modifying the overall pipeline.

For example,

- replacing TLS with Transit Least Squares 2.0,
- adding radial velocity fitting,
- adding CHEOPS observations,
- supporting PLATO,

would require only local modifications.

---

## Computational Efficiency

The most computationally expensive stage,

Bayesian inference,

is executed only after inexpensive algorithms have reduced the search space.

This significantly reduces runtime.

---

## Separation of Responsibilities

The pipeline intentionally separates

- data acquisition,
- preprocessing,
- signal detection,
- physical inference,

into distinct stages.

Each stage has clearly defined inputs and outputs.
